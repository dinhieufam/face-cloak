# Experiments

**Goal:** after the cloaked photo is inpainted, the mean ArcFace similarity should be **lower than E0**
(PhotoGuard PGD with a gray target) at the same ε.

**Rule:** change one thing at a time. Each experiment config inherits `configs/base.yaml` and overrides only its
own knob; `tests/test_config_and_masks.py` enforces this.

## Fixed protocol (`configs/base.yaml`)

| Setting | Value |
|---|---|
| Images | the 10 FFHQ ids in `data/dev_ids.txt` |
| ε | 16/255 |
| PGD | 200 iterations, `step_frac=0.125`, random init, seed 0 |
| Mask | MediaPipe FACE_OVAL, no dilation |
| Prompt | prompt 0 ("park"), the one the safety checker flags least |
| Seeds | {0, 1}, so 20 outputs per branch |
| τ | 0.1493, fixed (`eval.tau` in `base.yaml`, from `scripts/calibrate_tau.py`) |

## Order

0. **Step 0 (done):** `python scripts/calibrate_tau.py`, once for the whole team, gave τ = 0.1493. The value is committed in
   `configs/base.yaml` (`eval.tau`) with the full output in `data/tau_calibration.json`. Do not re-run it per machine.
1. **E0** first. It also runs the random-noise control, and the clean and random outputs it produces are cached in
   `_shared/` and reused by every later experiment.
2. E1–E4 in any order. Each one only generates its own cloak branch.
3. `python scripts/compare_experiments.py` builds the results table.

## E0: baseline (`E0_baseline.yaml`)

No code change: PhotoGuard PGD toward a flat gray image, with the loss on the full image.

## E1: target image (`E1_pattern_target.yaml`, `cloak.target`)

Target `assets/targets/pattern.png`: saturated colour gratings at several scales plus an 8-px checkerboard,
generated by `scripts/make_targets.py`. It is far from gray and carries a lot of energy at the 8-px scale,
which is the VAE's downsampling factor. `assets/targets/checker8.png` is a simpler alternative for a side ablation.

*Expectation:* the decoded face gets textured instead of washed out, which should break identity cues more than
blurring does.

## E2: optimise the attacker's view (`E2_mask_aware.yaml`, `cloak.mask_aware`, `cloak.mask_jitter_px`)

The loss is computed on `attacker_view(x+δ, m) = (x+δ)·m + 0.5·(1−m)`, which is exactly what the inpainting VAE
receives (see [pipeline.md](pipeline.md)). Every iteration the mask is randomly dilated or eroded by up to 10 px,
so the cloak does not depend on one exact mask. The final iterate is evaluated with the true mask.

Notes:

- The gradient outside the face is zero, so δ there stays at its random initial value. This is harmless for the
  attack but lowers PSNR.
- `attacker_view(gray) = gray`, so the gray target needs no change. With other targets, the target also passes
  through `attacker_view` per image; this is handled automatically.
- Assumption to state in the report: the defender knows the attacker uses a face-oval-style mask. The jitter
  approximates not knowing the exact mask.

## E3: momentum PGD (`E3_momentum.yaml`, `cloak.momentum`)

MI-FGSM: `g ← 0.9·g + ∇ / mean|∇|` (normalised per image), then step along `sign(g)`.
*Expectation:* faster convergence but only a small improvement. Its main value is a clean optimiser comparison
for the report. Compare `cloak_out/figures/pgd_convergence.png` with E0's.
Optional follow-ups: Adam with projection, or APGD (Croce & Hein, 2020).

## E4: untargeted (`E4_untargeted.yaml`, `cloak.untargeted`)

Maximise `‖E(x+δ) − E(x)‖²` instead of pulling toward a target. The gradient is exactly zero at δ = 0, so a random
start is required (it is on by default). `loss_ratio_*` is NaN here; compare `latent_dist_cloak` instead, which
is reported for every experiment (higher means further from the clean latent).

Alternative to try next: use **another person's face** as the target (a different FFHQ image, passed through
`attacker_view` with the source image's mask).

## E1b: checkerboard target (`E1b_checker_target.yaml`, `cloak.target`)

Side ablation of E1: the pure black/white 8-px checkerboard `assets/targets/checker8.png`.

## E5: identity loss through the VAE (`E5_identity.yaml`, `cloak.loss: identity`)

Implemented in `src/facecloak/identity.py`: FaceNet InceptionResnetV1 (VGGFace2, `facenet-pytorch`) on a fixed
square crop around the MediaPipe face mask (+15%), 160×160, after the VAE round trip `D(E(x+δ))`. The manifest
reports `id_cos_clean` (round trip of the clean image) and `id_cos_cloak` (surrogate cosine after the attack).
The design notes below are what was implemented:

Optimise the metric directly instead of a latent proxy:

    min_δ  cos( F(D(E(attacker_view(x+δ)))), F(x) )      F = a differentiable face recognizer

- UniFace runs on ONNX and is not differentiable, so a PyTorch recognizer is needed, e.g. insightface IResNet
  ArcFace or `facenet-pytorch`. Optimise against a **different** model (e.g. FaceNet) and evaluate with UniFace's
  ArcFace, so that a good result reflects transfer rather than overfitting to the evaluator.
- Crop the face using the fixed source box and resize it to F's input size. Optionally combine with the latent
  loss: `λ·latent + identity`.
- Backpropagating through the VAE decoder at 512² in fp16 needs batch size 1–2 on a T4; the A5000 has more headroom.

## Combinations (Phase 4)

Not single-change experiments (`C*` files are exempt from the one-knob test and say what they combine in their
first line). Chosen from the Phase 3 / E5 winners:

| ID | Combines | Config |
|---|---|---|
| C1 | E5 identity loss + E3 momentum | `C1_identity_momentum.yaml` |
| C2 | E5 identity loss + E2 attacker's view (mask jitter ±10 px) | `C2_identity_maskaware.yaml` |
| C3 | E1 pattern target + E3 momentum | `C3_pattern_momentum.yaml` |

## Robustness (Phase 4)

`R_<base>_<variant>` runs repeat E0, E5 and C2 with one attack-side change (as config overrides, see
`slurm/lists/phase4*.txt`), with the random control on:

- `prompts12`: prompts 1 and 2
- `seeds4`: seeds 0–3
- `dilate10`: `mask.dilate_px=10`
- `eps8`: ε ∈ {8, 16}
- `jpeg75`: `inpaint.jpeg_quality=75` (every branch's input is JPEG-recompressed before the attacker)

To keep the defender's cloak fixed, copy the base experiment's `cloak_out/manifest.csv` into
`<root>/R_.../cloak_out/` before running. Stage 1 then reuses the base cloaks.

## Results

All numbers use 10 images × prompt 0 × seeds {0, 1}, with ε = 16/255, after excluding NSFW-flagged outputs.
Δ is paired over the same image and seed: Δ vs clean = sim_clean − sim_cloak, Δ vs random = sim_random − sim_cloak
(higher is better; 95% bootstrap CI). The table is generated by `python scripts/make_report.py`
(`<root>/report/tables/main.md`; robustness in `robustness.md`) and copied here unchanged.

τ = 0.1493 (Step 0, FAR 1% on 300 FFHQ faces, 44,850 impostor pairs; stored as `eval.tau` in `configs/base.yaml`)
